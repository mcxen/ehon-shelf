# GodGo 界面规范

这份文件是界面契约，版本 0.1.0。应用侧栏的「规范」渲染的就是它。改窗口、侧栏、设置、字体或快捷键时，改这份文件，不要另写一份。

## 窗口

主窗口默认 1100×720，最小 760×480，`StateKey` 是 `main`。设置窗口默认 860×640，最小 720×480，`StateKey` 是 `settings`。同时只开一个主窗口和一个设置窗口。

macOS 使用隐藏标题栏并保留交通灯，灯的位置是 (18, 23)。顶栏高 60。其他系统自绘最小化、最大化和关闭，不用交通灯。

半透明打开时，两个窗口使用侧栏材质。关掉时不用材质。外观可以是跟随系统、浅色或深色。

退出前询问默认打开。确认之后才真正退出。测试里没有活的应用对象，确认不会调用退出。

## 侧栏

侧栏默认宽 248，可拖到 200–420。双击分隔条回到 248。拖动过程中不保存设置；松开后只记下宽度。`CmdOrCtrl+B` 隐藏或显示。隐藏时主卡片左侧出现显示和扩展两个按钮。

行高 34，卡片与窗口边缘的间距是 8。分组可以折叠；折叠后如果当前模块在这个组里，那一行仍然留着。

分组和模块按这个顺序：

| 分组 | 模块 |
|---|---|
| 工作台 | 概览、规范、工作流、更新 |
| 资源 | 字体、图标、测试资源 |
| 开发 | 后端、前端 |

页脚从左到右是：在访达中显示项目、前往、设置，右侧是「外壳就绪」。显示项目只在找到含 `module godgo` 的目录、并且应用处于运行状态时打开该目录。

`CmdOrCtrl+K` 打开前往面板，列出模块、设置页和两条命令：隐藏边栏、检查更新。空查询时按这三类分组，输入后按子序列匹配。

点扩展列出三处登记：`backend/modules/modules.go`、`frontend/settings_pages.go` 的 `settingsPages`、`resources/workflow/tasks.json`。

## 主卡片

每张卡片先显示模块名和摘要。规范页接着渲染本文件。其他模块显示文案里的正文。工作流、字体、测试资源和概览在正文下还有一块：

- 工作流按目录里的分组列出任务，每条显示命令参数。运行按钮只在应用处于运行状态时启动任务。
- 字体列出 Inter 和 Noto Sans SC 的字重，并用当前字体栈画一行「GodGo 外壳 Ag」。
- 测试资源列出五类目录名。
- 概览额外显示外壳已接好的提示。

## 设置

设置从侧栏齿轮或 `CmdOrCtrl+,` 打开。左侧导航宽 212，搜索框的名字是「搜索设置」。`CmdOrCtrl+F` 把焦点放进搜索框。搜索没有命中当前页时，切到第一个有命中的页。内容在顶栏下滚动，顶栏使用滚动边缘。

| 页 | 控件 |
|---|---|
| 通用 | 语言（跟随系统、简体中文、English）、登录时打开、退出前询问、记住上次的模块 |
| 外观 | 跟随系统 / 浅色 / 深色、半透明材质、随包字体或系统字体、文字大小 0.9× / 1× / 1.1× / 1.25×、背景花瓣 / 薄雾 / 草地 / 暮色 / 纯色 |
| 更新 | 当前版本、检查更新、自动检查、自动下载并安装 |
| 工作流 | 保存配置后运行测试 |
| 通知 | 有更新、工作流完成、工作流失败、提示音。运行中的应用若不支持通知，显示说明 |
| 键盘 | 四条快捷键，回车后校验。写错不保存并提示。可以恢复默认 |
| 高级 | 配置文件、资源目录、源码目录、恢复默认、加载配置时发现的问题 |

恢复默认保留侧栏宽度、隐藏、折叠和当前模块。非法的枚举和快捷键在读取时改回默认，并记在高级页。

默认快捷键是 `CmdOrCtrl+B`、`CmdOrCtrl+,`、`CmdOrCtrl+K`、`CmdOrCtrl+U`。空字符串表示取消绑定。

## 字体

随包字体注册为 Inter 和 Noto Sans SC。界面请求 `Inter, Noto Sans SC`。Inter 只覆盖拉丁字母，简体中文使用 Noto Sans SC。两套都是 SIL OFL 1.1 的静态子集，与 AvaMedia 桌面端的子集相同。

选择系统字体，或字体文件没有加载成功时，使用桌面字体，不设置字体族。字号是 13 乘以文字大小，不在主题已有字号上再乘一次。

## 颜色

背景是花瓣、薄雾、草地、暮色、纯色。前四种沿用 Kero 的色块；纯色使用侧栏色。选中行、卡片和控件的层次也沿用 Kero，不另做一套配色。颜色定义在 `frontend/colors.go`。

## 工作流

任务目录是 `resources/workflow/tasks.json`。分组必须在文件里声明，任务的分组必须是已声明的，命令参数不能空。现在的分组是验证和发布：测试（`go test ./...`）、静态检查（`go vet ./...`）、构建（`go tool mygo build`）。

命令直接执行，工作目录是含 `module godgo` 的模块根。找不到根目录时任务不运行。输出保留最后 16KB。一次任务最长 10 分钟。

「保存配置后运行测试」只在设置内容变化时启动测试任务。只改侧栏宽度、折叠或当前模块不会启动。

## 更新

`mygo.json` 的公钥目前是占位，格式合法，不能校验真正的更新包。发布前换成 `go tool mygo keygen` 的公钥，私钥不要进仓库。`updates.github` 要改成实际的 `owner/repo`。

开发运行的副本不能给自己安装更新。设置里未启用更新时，版本行说明这一点。检查更新、登录时打开、自动检查和自动安装只在应用处于运行状态时调用系统接口。

## 文案

`resources/locales/zh-Hans.json` 和 `en.json` 的键一致。缺键先用简体中文，再用英文，最后显示键名。语言选跟随系统时，依次看 `GODGO_LANG`、`LC_ALL`、`LANG`，否则用简体中文。界面测试固定简体中文，这样标签不随机器语言变化。

## 文档

维护关系是：

- `AGENTS.md` 告诉 agent 先读哪份文件、改完要跑什么，不描述控件尺寸。
- `resources/docs/reuse.md` 规定组件和能力先查 MyGo、Onevra、Kero，并且禁止过度设计、过度防御、重复造轮子。
- 本文件描述已经实现的界面。侧栏「规范」用 Markdown 视图渲染这两份文件。
- `README.md` 说明目录和发布前要替换的两项配置。

这两份规范随 `resources/` 打进应用。`AGENTS.md` 和 `README.md` 留在仓库根，不打进应用。
